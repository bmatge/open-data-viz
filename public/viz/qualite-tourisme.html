Analyse de reproduction — Qualité Tourisme

Page d'origine : qualite-tourisme — 33 200 caractères de template, six ods-map (la même carte dupliquée pour les points de rupture), trois ods-select alimentés par des ods-facet-results, et une grille de cartes paginée à 12.

Ce qui a été simple

  • Le motif « annuaire cartographié » est un cas d'école. Une source, une recherche, des facettes, une carte, une grille de cartes : cinq balises, et les cinq vues se refiltrent ensemble. La page d'origine mobilise trois listes déroulantes câblées à la main sur des ods-facet-results, plus un système de vues (params.view) pour basculer carte / liste.
  • Une carte responsive, pas six. L'original duplique ods-map six fois pour couvrir les points de rupture, chaque copie portant les mêmes quinze attributs. dsfr-data-map est responsive par construction : une seule déclaration.
  • Le chargement, réglé d'avance. Leçon reprise de la page Plan de relance : la source passe par /exports/json. Les 3 604 établissements arrivent en une requête de 2,8 s, là où le mode adaptateur en aurait enchaîné 37.
  • Les facettes à 99 valeurs. L'attribut searchable ajoute un champ de recherche dans la facette Département — nécessaire ici, et absent de l'original qui déverse ses 99 départements dans une liste déroulante.

Ce qui a coincé

  • Les liens optionnels — moins optionnels qu'annoncé. La première version de cette analyse affirmait que site_web était « vide pour une partie des établissements ». Recompté sur l'export : 1 valeur nulle sur 3 604 — et 11 URL malformées (http:patisseriechapuis.fr, htts://…), ce qui est un problème de donnée, pas de template. email_de_l_etablissement et questionnaire_de_satisfaction sont renseignés sur 100 % des lignes : ils peuvent être des liens sans aucune conditionnelle. Pour le seul site manquant, une règle CSS (.odv-lien[href=""] { display: none }, dans site.css) retire le lien vide du flux — vérifié au navigateur : display: none sur le lien de « BEST HOTEL », visible sur les autres. AM-007 reste vrai en général, mais cette page n'en était pas un bon exemple.
  • Placer l'interface des facettes. dsfr-data-facets rend son interface là où la balise est écrite, alors que son id seul détermine le câblage. La balise doit donc être physiquement dans la colonne de filtres, avant les dsfr-data-query qui la consomment mais s'écrivent plus haut. On s'y fait, mais l'ordre du fichier cesse de refléter l'ordre du pipeline.
  • Relecture face au relevé visuel du portail. Ajouté : le courriel (lien mailto:), le bouton « Donner son avis » (lien vers le questionnaire de satisfaction, propre à cette marque), le site en lien cliquable, le code postal dans les champs de recherche. Corrigé : le KPI « activités représentées » affichait 12 — il comptait les lignes de la requête limitée à 12 du graphique ; une seconde requête sans limit donne 28, le chiffre du portail. Le KPI « départements » affichait 100 : les 146 lignes sans département formaient un groupe null — where="departement:isnotnull" ramène à 99. Vérifié : la facette Activité liste les 28 valeurs avec les effectifs exacts du portail (Office de tourisme 862, Camping 634…) ; les cinq encarts DROM s'affichent, Mayotte compris — vide comme sur le portail, le jeu n'y a aucun établissement (0 point dans l'export, Guadeloupe non plus). Manque encore : l'autocomplétion sur le nom et sur la commune/CP — dsfr-data-search n'a pas d'attribut de suggestions (attributs vérifiés dans le source : fields, operator, debounce, min-length, highlight, count…) ; la recherche filtre à la frappe, ce qui rend le bouton « Rechercher » sans objet. La « fiche établissement » est le panneau latéral de la carte, pas une page dédiée : la mini-carte de la fiche n'a donc pas de sens ici.
  • Aucun compte par facette côté serveur. Les compteurs affichés sont calculés sur les 3 604 lignes en mémoire — exact ici, mais ce serait faux si le jeu dépassait ce que l'on charge. Le mode server-facets existe pour ça, au prix de renoncer au filtrage instantané.

✅ Corrigé depuis — dsfr-data 0.25.0

10 des frictions décrites ci-dessus ont été comblées par la bibliothèque après cette reproduction. Le constat reste écrit tel qu'il a été rencontré — c'est la trace du banc d'essai ; le code de la page porte encore ses contournements, qui ne sont simplement plus nécessaires — à l'exception d'AM-011, dont le contournement a été retiré au lot 13 : la source est repassée en mode adaptateur avec fetch-mode="export". Verdict

Reproduction facile, la plus rapide des cinq à ce jour. Le motif « annuaire cartographié » est exactement ce pour quoi ces composants sont faits : 33 200 caractères de template deviennent une trentaine de lignes, sans perte de fonction, avec en plus la recherche dans les facettes, la carte accessible et les DROM dans le cadre. Le seul point de friction — les liens optionnels — est un manque déjà consigné ; la relecture face au portail a surtout montré que cette page l'illustrait mal (1 site manquant sur 3 604) et que deux de ses KPI étaient faux par construction.

Constats consignés au registre des retours : AM-007 (liens optionnels), AM-013 (placement de l'UI des facettes), AV-008 (carte responsive unique).
